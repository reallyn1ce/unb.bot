# Economy Bot

Discord-бот с полноценной экономикой для серверов: у каждого сервера свой баланс, своя инфляция, свой Центральный банк и свой государственный бюджет. Включает казино, фондовую биржу, бизнесы и кредиты.

## Функционал

- 🏦 **Центральный банк и резерв** — эмиссия (`!print-money`) и сжигание денег (`!burn-money`); все заработки выплачиваются из резерва ЦБ, налоги уходят в госбюджет
- 🏛️ **Государственный бюджет** — пополняется подоходным налогом, налогом на бизнес и другими сборами
- 📉 **Налоги и инфляция** — инфляция считается по чистой эмиссии за 24 часа и влияет на доход бизнесов (коэффициент настраивается пресетом)
- 💰 **Экономика игрока** — баланс (наличные + банк), переводы, `!work`, `!crime`, `!slut`, `!rob`, вклады и снятие, топ игроков
- 🏢 **Бизнесы** — покупка, улучшение уровней, почасовой доход
- 💳 **Кредиты** — выдача и погашение с ограничением по сроку и штрафом за просрочку
- 🎰 **Казино** — слоты, блэкджек, русская рулетка (соло и с друзьями), статистика игрока
- 📈 **Биржа** — IPO компаний со свободным обращением акций, книга лимитных заявок, торговля между игроками, дивиденды из прибыли компании, котировка по спросу/предложению и финансам компании (см. раздел «Биржа V2»)
- 📊 **Статистика и графики** — сводка `!economy`, графики денежной массы по запросу (`!graphs`) и автоматически раз в сутки
- ⚙️ **Настройки** — панель `/settings` для администраторов (пресеты, кулдауны, награды `!crime`/`!slut` и прочие значения вручную, включение модулей, кастомные тексты)
- 🌐 **Health-check** — HTTP-эндпоинты `/` и `/health` для хостингов

Команды, которые есть и в префиксном (`!`), и в слеш-виде, помечены ниже как «`!` и `/`». Админские команды `!print-money`, `!burn-money`, `!set-chart-channel`, `!graphs` — только префиксные.

## Запуск

```bash
python bot.py
```

При старте бот проверяет обязательные переменные (`DISCORD_TOKEN`, `MONGO_USER`, `MONGO_PASSWORD`), подключается к MongoDB, создаёт индексы и документы ЦБ и бюджета для всех серверов и синхронизирует слеш-команды. Статус активности (Activity/Presence) бот не устанавливает.

## Автоматические графики

`!set-chart-channel [#канал]` (администратор) задаёт канал, в который раз в сутки в 18:00 UTC бот присылает графики денежной массы (24 часа и вся история). Без настроенного канала автопубликации нет; график по запросу доступен через `!graphs`. Снапшоты денежной массы для графиков бот делает каждые 5 минут независимо от канала.

## Discord Intents

Бот запрашивает только `guilds`, `guild_messages` и `message_content` (нужен для префиксных команд `!`). **Server Members Intent не нужен** — имена участников подгружаются через `fetch_member`. Следствие: в префиксных командах игрока лучше указывать упоминанием (`@user`); поиск по имени или ID без Members Intent может не работать (слеш-команды не затронуты).

## Транзакции

Все денежные операции выполняются в транзакциях MongoDB через `EconomyBot.run_tx`. Временные ошибки (`TransientTransactionError`, например write-conflict на документе резерва ЦБ) и неизвестный результат коммита обрабатываются автоматически: транзакция перезапускается (до 5 попыток с короткой паузой). Бизнес-ошибки (`EconomyError`: не хватает средств, кулдаун и т.д.) откатывают транзакцию без повторов.

## Проверка БД

Два чтения-fallback для старых документов настроек оставлены намеренно — миграция их никогда не переписывала. Если перед их удалением нужно убедиться, что они не нужны, выполните в `mongosh`:

```js
// 1) документы со старыми top-level кулдаунами (вместо eco.cooldown_*)
db.guild_settings.countDocuments({ $or: [
  { cooldown_work: { $exists: true } }, { cooldown_crime: { $exists: true } },
  { cooldown_slut: { $exists: true } }, { cooldown_rob: { $exists: true } } ] })

// 2) документы с пресетом, но без eco.inflation_multiplier
db.guild_settings.countDocuments({ "eco.preset": { $exists: true },
                                    "eco.inflation_multiplier": { $exists: false } })

// 3) нет ли старого уникального индекса только по user_id (мешает мультисерверности)
db.users.getIndexes(); db.businesses.getIndexes(); db.casino_stats.getIndexes()
```

Если оба счётчика равны `0`, а в индексах нет уникального ключа `{ user_id: 1 }` без `guild_id`, fallback-чтение в `EconomyBot.get_settings` можно удалить.

## Обновление с версии с ИИ, `!daily` и отчётами (8.0.0)

Удалены: ИИ (Groq/OpenAI-совместимый API, кнопки в `/settings`, переменные `AI_*`), ежедневные экономические отчёты и `!set-report-channel`, команды `!daily`, `!cb`/`/cb` и `!help`/`/help`, а также установка статуса активности. Модуль «Ежедневный бонус» и настройки `daily_min`, `daily_max`, `cooldown_daily` убраны из `/settings` и пресетов.

Данные в БД бот **не удаляет и не мигрирует**: старые поля (`ai_enabled`, `report_channel_id`, `modules.daily`, `eco.daily_*`, `eco.cooldown_daily`, `users.last_daily`) остаются в документах и просто не читаются; записи журнала транзакций за прошлые `!daily` сохраняются. Автопубликация графиков продолжает работать с уже заданным `chart_channel_id`; поле `last_automation_date` сохранено, поэтому в день обновления графики не продублируются. Если хотите почистить неиспользуемые поля вручную (необязательно):

```js
db.guild_settings.updateMany({}, { $unset: { ai_enabled: "", report_channel_id: "",
  "modules.daily": "", "eco.daily_min": "", "eco.daily_max": "", "eco.cooldown_daily": "",
  cooldown_daily: "" } })
db.users.updateMany({}, { $unset: { last_daily: "" } })
```


## Биржа V2

**Выпуск.** `!stock create` (по-прежнему 100 000 в резерв ЦБ): выпускается 1000 акций — 60% получает основатель, 40% компания выставляет на рынок по 100 (первичное размещение). Деньги от продажи этих акций идут **в казну компании**, а не основателю, поэтому торговля не зависит от денег основателя. Основатель не может опустить долю ниже 25% (250 акций): открытые заявки на продажу считаются уже проданными, поэтому новая заявка допустима, только если свободный остаток после неё не ниже минимума (доступно к продаже = свободные акции − 250). Лимит проверяется и в самой БД условным списанием.

**Торговля.** `!buy ТИКЕР N` / `!sell ТИКЕР N` без цены — по рынку (исполняется по лучшим встречным заявкам в допустимом диапазоне, остаток отменяется). С ценой — лимитная заявка, она лежит в книге (`!stock book`) до исполнения или отмены. Исполнение идёт по цене уже лежащей заявки, приоритет: цена, затем время. Цены заявок — целые. Деньги покупателя и акции продавца **замораживаются при размещении заявки**, поэтому продать больше, чем есть, или потратить больше, чем есть, невозможно. Сделки с самим собой исключены. Комиссия 2% с продавца: 60% — прибыль компании, 40% — госбюджет.

**Дивиденды.** Раз в 24 часа компания выплачивает `payout_ratio` (по умолчанию 50%, меняет основатель: `!stock dividend`) от накопленной **прибыли** (комиссии со сделок). Платится только из казны компании и только при наличии прибыли; пропорционально акциям (акции в заявках тоже учитываются, акции самой компании — нет); с налогом НДФЛ сервера в госбюджет. Резерв ЦБ не используется, эмиссии нет. Взносы основателя (`!stock invest`) и выручка от первичного размещения — капитал, а не прибыль, на дивиденды не идут. Выплата идемпотентна: один документ в `stock_dividends` на компанию и период.

**Цена.** Котировка — взвешенная объёмом и свежестью медиана сделок вторичного рынка за 24 часа (без фиксированного шага). Защита: нужно ≥3 разных игроков в окне; вклад пары «покупатель—продавец» ограничен 34% объёма; прежняя цена входит с весом «инерции»; цена заявки в пределах ±20% от котировки, суточный лимит ±30%, нижняя граница — 50% балансовой стоимости. Финансы компании: если торгов нет сутки, котировка медленно тянется к справедливой цене (казна на акцию + прибыль за 30 дней), а цена первичного размещения следует за рынком. Случайных движений больше нет. Все параметры — константы `STOCK_*` в начале `bot.py`.

**Коллекции.** `stocks` (компания: `supply` — выпущено, `treasury`, `profit_pool`, `payout_ratio`, `price`), `stock_holdings` (свободные акции; `user_id=0` — акции компании), `stock_orders`, `stock_trades`, `stock_dividends`, `stock_payouts`. Инвариант, который проверяет `!stock audit`: Σ позиций + Σ акций в заявках на продажу = `supply`. Все документы и запросы содержат `guild_id`; деньги в казнах и заявках входят в денежную массу `!economy`.

**Миграция** (автоматически при старте, идемпотентна, в транзакции на компанию): сохраняются цена, `supply`, история и все позиции игроков. Старым компаниям добавляются поля V2 (казна 0, прибыль 0). Единственное перемещение: доля основателя сверх 60% выставляется его собственной заявкой на продажу по текущей цене (раньше эти акции и так продавались «у владельца») — он может отменить её через `!stock cancel`. Если сумма позиций расходилась с `supply`, нехватка отдаётся компании, избыток увеличивает `supply`.

> Прибыль компании сейчас формируется только биржевыми комиссиями; другие источники можно добавить, начислив их в `profit_pool` и `treasury`.

Тесты на поддельной MongoDB: `python tests/test_exchange.py` и `python tests/test_market.py` (внешние библиотеки заменяются заглушками).


## Награды `!crime` и `!slut` (настройки сервера)

`/settings` → «⚙️ Кастомная» → «🕵️ Награды crime/slut»: четыре значения — минимум и максимум для `!crime` и для `!slut`. Награда выбирается случайно в диапазоне. Значения целые, от 0 до 1 000 000; отрицательные и «минимум больше максимума» не сохраняются. По умолчанию (и во всех пресетах) — прежние диапазоны: `!crime` 300–900, `!slut` 200–700, поэтому у существующих серверов выплаты не меняются. Выбор пресета сбрасывает ручные значения вместе с остальными настройками.

Механика команд не менялась: шанс успеха (`crime_chance`), кулдауны, штраф за неудачу (в госбюджет), тексты. Награда платится **из резерва ЦБ** (резерв → наличные), в одной транзакции с кулдауном: если в резерве не хватает денег, выплаты нет, деньги не создаются и кулдаун не тратится — игрок видит сообщение «В резерве ЦБ недостаточно средств». При диапазоне 0–0 команда работает как раньше, но ничего не платит.

## Русская рулетка: «🔄 Играть снова»

Под итогом раунда (соло, мультиплеер, выигрыш, проигрыш, «Забрать», автозавершение по таймеру) появляется кнопка «Играть снова» (активна 2 минуты). Её могут нажать только участники раунда — каждый для себя, одновременно. Нажатие открывает форму ставки (число или `all`) — ничего из прошлого раунда не переносится, ставку и режим (соло / с друзьями) нужно выбрать заново. Баланс проверяется при нажатии, при отправке формы и ещё раз атомарно при списании; ставка списывается один раз — после выбора режима. Кнопка одноразовая для каждого игрока: повторные нажатия по старому сообщению ничего не запускают, пока идёт его игра. Кнопки завершённого раунда (выстрел / забрать) отключены. Правила, множители и выплаты рулетки не менялись; остальные игры (слоты, блэкджек) по-прежнему перезапускаются с прежней ставкой.
